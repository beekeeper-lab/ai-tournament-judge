# Calibration Report

`persona` is what produced this document and must resolve in
`framework/personas.md` as `name@x.y.z`. A calibration exercises the whole panel,
so name the component that ran it — the orchestrating skill — and list the judge
personas under `## Samples used`. A calibration sample is not a roster team:
`sample_id` names it, and it carries no `team_id`.

Calibration runs the panel against sample submissions before official judging to
find ambiguous rubric language. It may clarify wording. It may **not** teach the
panel a preferred winner or force agreement.

## Samples used

| Sample ID | Intended difficulty | Source | Why it was chosen |
|---|---|---|---|

Use at least one clearly weak case and one solid expected case. Samples must be
synthetic or explicitly cleared for this use; never a live entrant.

## Disposition

| Change | Rubric version before | Rubric version after | Rerun required |
|---|---|---|---|

A rubric change during an active event is prohibited. If calibration finds a
defect after judging begins, create a new rubric version and explicitly restart
or migrate affected work.

## Limitations

State what calibration did not cover: criteria with no sample coverage, evidence
classes not exercised, and any persona not run.

## Validation

- [ ] At least two samples, spanning weak and solid
- [ ] No sample is a live entrant
- [ ] Scores produced by the deterministic script
- [ ] No agreement was coerced
- [ ] Rubric changes versioned, or none made
