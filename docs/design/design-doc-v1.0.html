1. Summary

The AI Tournament Judge (ATJ) is a repository-local framework that evaluates student software submissions. Four LLM judge personas score each submission independently against one shared rubric. A consolidator merges their reports. A seeded bracket pairs teams, and each matchup is judged twice in reversed presentation order. The output is a private judging record, a team-facing dossier per team, and approved public summaries. Every number, validation, random draw and state change is produced by a deterministic Python CLI, atj. LLM judgment is never described as reproducible.

2. What it is and why

An LLM can read a codebase and form a view on its quality. On its own that view is not a result anyone can defend: it is not reproducible, it can be steered by text in the submission, and a single model has a single set of blind spots. ATJ wraps the judgment in machinery that makes a disputed result answerable (README.md, "What is deterministic").

  • Several lenses, one rubric. Four personas (backend, frontend and UX, security and operations, product and agentic design) investigate with different emphasis. Weights live only in the rubric, so a persona cannot change what matters (framework/rubrics/submission-evaluation.md).
  • Independence, then synthesis. No judge sees another's report. Consolidation happens afterwards and flags disagreement instead of averaging it away (framework/policies/judge-independence.md, framework/rubrics/panel-consolidation.md).
  • Order-balanced comparison. A head-to-head matchup runs twice, A-first and B-first, because presentation order biases LLM comparisons. A winner is confirmed only when both orders agree and the margin clears the close-call band (framework/rubrics/head-to-head.md).
  • Evidence first. Every score cites an evidence package pinned to an immutable commit. A missing observation is NE, never a zero.
  • Three products. Private deliberation, team-facing feedback and public ceremony content have enforced boundaries.

The project is a work in progress. Its two real events were run to find what the framework gets wrong, and they decided nothing (README.md, events/trial-2-2026/event.md "Purpose").

6. Per-team judging

Mechanics that matter

  • Evidence package identity. evidence_package_id is derived from the event, team, commit and a digest of the manifest content. Re-preparing identical evidence yields the same ID. Any change yields a new one, which is what makes staleness detectable (docs/implementation-detail.md D2).
  • Bidirectional citations. The manifest's observation table declares which requirements each observation supports, and atj validate reports checks that the requirements table agrees (CHANGELOG 0.3.0-beta). This is a shape check. It cannot tell that a citation points at the wrong content (memory: validate reports cannot verify citations).
  • Judge scores. Each judgment's front matter carries one raw score or NE per criterion ID and a confidence. No weight and no total appear in a judgment (framework/templates/individual-judgment.md). atj render judgment generates the scores table from that front matter.
  • Consolidation. atj score computes the weighted panel result and the agreement class per criterion from the thresholds in panel-consolidation.md. The consolidator writes prose. The numbers are generated into the report, and reports.check_consolidation reloads judgments, reapplies approved adjudications and fails on any mismatch (docs/implementation-detail.md D12).
  • Accepted NE. score_override.resolved_score: NE records that an official reviewed the criterion and the NE stands. The panel stays unfinalized by decision. Both trial-2 teams ended this way.

7. Bracket and matchups

Bracket

atj bracket build --event-dir <dir> --seed <seed> places eligible teams by a seeded search with fixed restarts, so the result is a pure function of seed and inputs. The bye policy, default and team range come from framework/rubrics/bracket-assignment.md. Each constraint reports satisfied, maximized, violated, not-applicable or infeasible. feasible: false is a legitimate outcome that an official must accept in writing (docs/implementation-detail.md D5). atj bracket verify --event-dir re-derives every constraint from the roster instead of trusting the file's own audit block, and --reproduce <roster.json> redraws from the recorded seed (D6).

Matchup

The matchup rubric forbids selecting on initial totals (head-to-head.md). Match identifiers come from the drawn bracket, not from a second assignment (D14). A known side effect: atj bracket advance writes winner into bracket.json, which stales the bracket:draw unit and makes --reproduce fail on every completed bracket (W25, W27).

8. Audit, repair and staleness

The judging-auditor agent is the only control that has caught wrong citations, invented counts and false reasons. atj validate reports returned zero findings at every stage of live-trial-2026 while the manifests held nine misdirected citations (CHANGELOG 0.3.0-beta). Every repair round in both real trials introduced new defects, so each repair is re-audited, scoped to its diff (memory: audits catch their own repairs).

Rules learned from running the loop

  • The auditor writes only its report and recommends record, approve, gate and advance commands. It never runs them. It has Bash and once re-recorded a unit itself (memory: auditor must not run state commands).
  • A repair is derived from the primary source, never copied from the audit's own repair: field. Three of five trial-2 bracket rounds introduced a defect that came from the auditor's suggested repair (memory: audit findings carry their own errors).
  • Record a unit after the last edit to anything it digests. Take ledger times from git. Never estimate a time or force a commit date (trial-2 final audit FB2).
  • atj event gate reads each finding's scope and blocking, not the verdict alone (gate_blocking_findings, fix-plan D16).

9. Privacy and publication

The repository is public. visibility: private is a marker of intent that the git remote does not read. Everything committed under events/ is world-readable once pushed. For trial-2-2026 both submissions are public and the event-director approved disclosure (events/trial-2-2026/overrides/ovr-trial-2-2026-publication-disclosure.md). For live-trial-2026, whose two submissions are private repositories, the disclosure decision is still open (O33).

Known gaps: the gate is a shape check. In trial-2 a short submission commit, a repository URL, an affiliation and an integer margin each passed as CLEAR in a public draft (W22). The template's required framework_commit fails the gate at full length (W21). public_scores is one event-wide flag with no per-team control (W7).

The status ledger (status.md)

  • Front matter: current_stage, blocked, stage_gates (gate to pending or passed), gate_evidence (gate to audit artifact path), units, overrides, last_updated.
  • Unit: unit_id (for example judging:<team>), stage, state (pending, in-progress, complete, stale), input_digest, outputs, audit_result, completed_at. Re-recording over an unchanged digest keeps the original completed_at; a changed digest restamps it; --completed-at overrides both (record_unit). There is no separate recorded-at time (W28).
  • Body: stage-gate checkboxes that atj event validate compares to the ledger (fix-plan D30), a team progress table, blockers and adjudications, and an append-only activity log of every command, repair and audit with input identity and result.

Adjudications and overrides

  • Adjudication (adjudications/): answers a question the framework returned to a human. Fields include scope (the score loader applies only criterion scope), criterion, trigger, resolution with score_override, advances_team for matches, decided_by, decision_authority (human-official may move a total, agent-substituted may not, absent means the latter), substitution_reason, and append-only amendments.
  • Override (overrides/): a recorded human decision that steps over a rule or accepts a deviation, with scope and authorized_by. Trial-2 wrote overrides for the infeasible affiliation constraint, the publication disclosure, and two model substitutions.
  • Gate bypass: atj event advance --force-reason records an entry in status.overrides. atj event overrides --review <i> --official <role> records that a person read it, never that it was justified.

13. Hooks, tests and release checks

Hooks (.claude/hooks/)

Guard rails, not a security boundary. They run with the operator's permissions and fail open on their own errors (lib.sh). Claude Code ignores project permissions.allow until the workspace is trusted, so nothing depends on it.

  • pre-write.sh: blocks event or framework artifact writes on main, edits to an active event's frozen contracts after judging begins, and hand-edits of events/*/public/.
  • pre-advance.sh: blocks a stage advance whose gate is pending, and direct host execution of submission code.
  • post-write.sh: validates what was written; advisory.
  • session-start.sh, user-prompt.sh: report framework health, branch and each event's next safe action.

Tests

21 modules in tests/. Regression files name the defect each test locks down (test_live_trial_regressions.py, test_tier1..3_regressions.py, test_final_audit_regressions.py, test_release_audit_regressions.py, test_audit_regressions.py). Live egress tests need a container runtime and ATJ_LIVE_SANDBOX=1 and are skipped by default. Bracket tests sweep every size, policy and many seeds. A committed-audit regression in test_tier1_regressions.py was adjusted when trial-2 completed with the findings: audit shape (commit 381920a).

atj release-check

At 95ae008 it reports PASS on: rubric, schemas, personas, templates, claude components, single-source, template schemas, version-skew, packaging, version archive, write contracts, signed approvals (completed events frozen), sample event. CI also installs the wheel into a fresh virtualenv and runs release-check from /tmp. The full validation chain is in README.md "Validation" and docs/release-checklist.md.

16. Lessons learned

CodeLessonEvidence
L1A green atj validate reports means well-formed, not true. The LLM audit is the only citation control.CHANGELOG 0.3.0-beta; memory validate reports cannot verify citations
L2Every repair round introduces defects. Re-audit the repair diff, always.Both trials; memory audits catch their own repairs
L3An audit finding can be wrong. Derive a repair from the source, never from the audit's repair text.trial-2 consolidation P1, bracket rounds
L4One wrong number in an evidence manifest becomes several wrong judge findings, because judges trust the package.live-trial team-podcast manifest
L5Consolidation errors run one way: corroboration inflated, single-judge concerns dropped. Count judges per claim.trial-2 consolidation, final audit advisory
L6Judges report tool blindness as fact. An absence claim needs git ls-files.trial-2 judgments F1, W11
L7A causal claim can be false while every number around it is right. Check stated reasons with a command and a control.trial-2 configuration, memory repository visibility is checkable
L8Running the documentation finds defects that reading the code does not.live-trial D29, D31
L9Approving an artifact rewrites it and stales every unit that digests it. Approve before recording units.trial-2 final audit FA7 rows
L10The auditor must not run state commands.trial-2 tournament round four
L11Take ledger times from git. Never estimate or force a commit date.trial-2 final audit FB2
